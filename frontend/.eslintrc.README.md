# How user-visible copy is held to next-intl

Two rules in `.eslintrc.json`, over the whole of `src`:

- **`react/jsx-no-literals`** covers JSX *children* — body copy, table headers, chip text,
  the em-dash used for an empty value.
- **`no-restricted-syntax`** covers the *attributes* a user actually reads: `placeholder`,
  `title`, `description`, `label` and `aria-label`. `label={t("…")}` passes; `label="Name"`
  and `label={"Name"}` are errors. A whitespace-only value passes — `<Field label=" ">` is a
  layout spacer, not copy.

## Why attributes are not `noAttributeStrings`

The rule's own attribute mode flags *every* string attribute, `className` included, which is
unusable in a Tailwind codebase — that is why `ignoreProps` is on. The AST selector does the
same job precisely, naming the five props whose values reach a screen or a screen reader and
ignoring the rest. It costs no new dependency.

## What neither rule can see

Both rules only look at JSX. They say nothing about:

- **Toast and error copy** — `toast.show({ title: "Saved" })` is an object property.
- **Template literals in attributes** — ``aria-label={`Edit ${name}`}``.
- **Default parameter values** — `placeholder = "Search…"` in a component's signature.
- **Literals inside JSX expressions** — `{cond ? t("a") : "Fallback"}`.
- **Strings returned from plain modules** — a label map in `features/gl/types.ts`.
- **Whether a key exists.** To ESLint every `t()` call looks alike.

Each of those hid real English during the issue #6 backfill, and each is worth a look in
review. The last one is covered by `src/features/subledger/i18n-coverage.test.ts`, which
resolves every `t("…")` key in `src` against `en.json` and fails on one that is not there.
That file also keeps a regex scan of the same five attributes — redundant with lint by
design, cheap insurance that survives someone switching a rule off — and holds the `arap`
catalogue to the same key set for both roles.

## The one exemption

`src/app/design/**` — the design-system gallery and its three prototypes. They are an
internal reference rather than product surface, and `src/app/design/layout.tsx` 404s the
whole subtree outside development so the exemption cannot reach a tenant. `layout.test.tsx`
holds that gate.
