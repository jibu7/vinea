# How user-visible copy is held to next-intl

Two rules in `.eslintrc.json`, currently scoped to the P4 AR/AP screens, keep every string a
user reads out of the source and in the catalogue:

- **`react/jsx-no-literals`** covers JSX *children* — body copy, table headers, chip text, the
  em-dash used for an empty value.
- **`no-restricted-syntax`** covers the *attributes* a user actually reads: `placeholder`,
  `title`, `description`, `label` and `aria-label`. `label={t("…")}` passes; `label="Name"` is
  an error.

## Why attributes are not `noAttributeStrings`

The rule's own attribute mode flags *every* string attribute, `className` included, which is
unusable in a Tailwind codebase — that is why `ignoreProps` is on. The AST selector does the
same job precisely, naming the five props whose values reach a screen or a screen reader and
ignoring the rest. It costs no new dependency.

Until this commit those five props were covered only by
`src/features/subledger/i18n-coverage.test.ts`, a scan rather than a lint rule. A scan finds
what is already there; it does not fail the next screen that lands with `placeholder="Code"`.
The test stays as the catalogue check — it also asserts the `arap` key set does not drift
between roles — but the attribute check is lint's job now.

## Scope

Both rules are scoped to the AR/AP file list while the P3 backfill runs
([issue #6](https://github.com/jibu7/vinea/issues/6)). When it lands, they move to top-level
`rules` and the only remaining exemption is `src/app/design/**` — the design-system gallery and
its prototypes, which are an internal reference, not product surface, and 404 outside
development (`src/app/design/layout.tsx`).
