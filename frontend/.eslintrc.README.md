# Why `react/jsx-no-literals` is scoped, and what it does not cover

`.eslintrc.json` turns `react/jsx-no-literals` on for the P4 AR/AP screens only. Those
screens are fully externalised through next-intl, and the rule is what keeps them that way:
any user-visible string reaching JSX as a literal — body copy, table headers, chip text, the
em-dash used for an empty value — is an error inside that scope.

`ignoreProps` is on deliberately. The rule's attribute mode (`noAttributeStrings`) flags
*every* string attribute, `className` included, which makes it unusable in a Tailwind
codebase. Attribute copy that a user actually reads — `placeholder`, `title`, `aria-label`,
`description` — is covered instead by `src/features/subledger/i18n-coverage.test.ts`, which
scans the same file list for literal values in those specific props.

The rest of the app (P3's GL and Common screens) does **not** pass this rule yet. That is
tracked, not inherited silently — see [issue #6](https://github.com/jibu7/vinea/issues/6), and
`docs/i18n-backfill-p3.md` for the file list as it stood when P4 step 6 was accepted.
